## 1. はじめてのログイン

運営の担当者のアカウントは、開発・保守の担当者が作ります（自分では登録できません。[開発・保守ガイド](maintainer.md#7-運営の担当者を足す外す)）。

1. 「Your temporary password」という件名のメールが Cognito から届きます（迷惑メールに入ることがあります）
2. 運営の画面を開くと、ログインの画面に移ります。メールアドレスと仮のパスワードでログインします
3. 新しいパスワードを決めます（12 文字以上、大文字・小文字・数字・記号を含む）
4. 認証アプリ（Google Authenticator、Microsoft Authenticator など）で表示された QR コードを読み、6 桁のコードを入れて MFA を登録します
5. 運営の画面が開きます。上に「開発用」と出ていれば開発用の環境です

- MFA はすべての利用者に必須です。認証アプリの入った端末をなくしたら、開発・保守の担当者に MFA の登録のやり直しを頼んでください
- 画面のログインは、ブラウザのタブを閉じると消えます（トークンをタブの中だけに置くため）。もう一度開くとログインの画面に移ります
- 運営の担当者でないアカウント（チャンネル提供者）でログインすると「チャンネル提供者の画面は準備中です」と出ます

## 2. 画面の地図

| メニュー | できること |
|---|---|
| 概要 | 最新の公開と期限、署名鍵の状態をひと目で確かめる |
| 公開 | 公開の履歴を見る。今すぐ作り直す |
| 署名鍵・鍵セット | KMS の鍵を署名鍵として登録する。鍵セットの入力を作り、ルート鍵で署名した鍵セットを登録する |
| 提供者 | チャンネル提供者・素材提供者の一覧・詳細、停止・再開、上限の変更、その提供者のチャンネル・素材集 |
| チャンネル | チャンネル ID で探して状態を見る。取り下げる |
| スタジオ | スタジオを出す承認の審査、申し出、通報されたスタジオ（[13](#13-スタジオ)） |
| 一言 | 通報された一言、締め出し（[14](#14-一言)） |
| 置けない区画 | スタジオも一言も置けない区画（[15](#15-置けない区画)） |
| 操作の記録 | 月ごと、または対象（チャンネル提供者・チャンネルなど）ごとに記録を見る |

状態を変える操作には、すべて「理由」を入れます。理由は操作の記録に残り、取り下げの理由は散策者にも見せます。

## 3. 日々の確認

「概要」で次を見ます。

| 項目 | 正常 | 気にすること |
|---|---|---|
| 最新の公開 | 毎日 03:00 ごろの `daily`、または操作のたびに増えている | 2 日以上増えていない |
| 期限 | 発行から 14 日後 | **あと 3 日を切ると赤字で警告**。毎日の作り直しが止まっている。「公開」で作り直しを試し、だめなら開発・保守の担当者へ |
| 署名鍵 | 使っている鍵が `active`、期限まで 1 か月以上 | 期限が近い → [署名鍵の入れ替え](#53-署名鍵の入れ替え半年ごと) |

## 4. 公開

承認・取り下げ・鍵セットの登録のたびと、毎日 03:00 に、リストは自動で作り直されます。ふだん手で公開する必要はありません。

**今すぐ作り直す**: 「公開」で理由を入れて「今すぐ作り直す」を押します。数秒後に履歴へ新しい `seq` が増えます（きっかけ「手動」）。増えないときは [困ったとき](#12-困ったとき)。

履歴の各行は、`seq`、公開の日時、期限、きっかけ（承認・取り下げ・鍵の移し替え・鍵セット・毎日・手動）、載せたチャンネルと取り下げの数、署名した鍵、リスト本体の SHA-256 です。

## 5. 署名鍵と鍵セット

### 5.1 しくみ

- **署名鍵**は KMS の中にあり、取り出せません。開発・保守の担当者が作ります（CDK の設定に鍵 ID を足して配備）
- **鍵セット**は「どの署名鍵を、いつからいつまで使ってよいか」の一覧で、**ルート鍵**がオフラインで署名します。ルート鍵はこのシステムに入れません
- 公開の処理は、鍵セットに載っていて、期間内で、状態が `active` の鍵で署名します

| 署名鍵の状態 | 意味 |
|---|---|
| `registered` | 登録したが、まだ鍵セットに載っていない（署名に使わない） |
| `active` | 今の鍵セットに載っている（署名に使う） |
| `retiring` | 前の鍵セットにはあったが、今の鍵セットにはない |
| `revoked` | 鍵セットで失効させた。二度と使わない |

### 5.2 鍵セットを登録する

1. 「署名鍵・鍵セット」の表で、鍵セットに入れる署名鍵にチェックを入れます
2. 有効期間（日、366 以下。既定は 180）を決めます
3. 表示された JSON を「コピー」し、USB メモリなどでルート鍵のある**オフラインの端末**に写します（ファイル名 `keyset-input.json`）
4. オフラインの端末で署名します（合言葉は環境変数で渡す）

   ```sh
   ROOT_KEY_PASSPHRASE=… sanpo-root-key sign-keyset --root-key root-key.pem --in keyset-input.json --out keyset.json
   ```

   署名の前に、鍵 ID の重なり、有効期間（1 年以内）、公開鍵の形を確かめます。問題があれば署名しません
5. できた `keyset.json` を運営の端末に戻し、中身を「署名した鍵セットを登録する」に貼り付けて登録します
6. 登録すると、載せた鍵が `active` になり、リストが作り直されます

登録が拒まれる主な理由: ルート鍵の署名でない（`invalid_signature`）、`seq` が今のもの以下、載せた鍵が未登録、または KMS の公開鍵と違う（`keyset_invalid`）。

### 5.3 署名鍵の入れ替え（半年ごと）

署名鍵は半年ごとに入れ替えます（ARCH-001 A-8）。新旧の鍵を一時的に両方載せるので、アプリが止まることはありません。

1. 開発・保守の担当者に、新しい鍵 ID（例 `k-2027-04`）の KMS の鍵を作ってもらい、ARN を受け取る
2. 「KMS の鍵を登録する」に鍵 ID と ARN を入れて登録する（`registered`）
3. 新旧の両方にチェックを入れて鍵セットを作り、署名して登録する（両方 `active`）
4. 数日たったら、新しい鍵だけにチェックを入れて鍵セットを作り、署名して登録する（古い鍵は `retiring`）

### 5.4 署名鍵を失効させる

署名鍵が漏れた疑いがあるとき（管理システムが乗っ取られた疑いを含む）は、[緊急時の対応](#11-緊急時の対応)のとおり、新しい署名鍵を用意したうえで、古い鍵 ID を `revokedKeys` に入れた鍵セットを作ります。画面が作る入力の `revokedKeys` には、今の鍵セットの失効の一覧が入っています。失効させる鍵 ID を、署名の前に手で足してください。失効させた鍵で署名されたリストは、アプリが署名の日時にかかわらず使いません。

## 6. チャンネル提供者の管理

「チャンネル提供者」では、状態で絞り込んで一覧を見られます。詳細では、連絡先、アカウントID、今日の申請・試用チケットの数、チャンネルを見られます。

| 操作 | どうなるか |
|---|---|
| **停止する** | 申請・試用チケット・鍵の紐づけを受け付けなくなる。**公開中のチャンネルはそのまま**残る。止めたいときは、別にチャンネルを取り下げる |
| **停止を解く** | 鍵を紐づけ済みなら `active`、まだなら `pending_key` に戻る |
| **上限を変える** | チャンネル数、1 日の申請、1 日の試用チケットを、そのチャンネル提供者だけ変える（0〜1000）。空欄にして保存すると既定値（5・20・10）に戻る |

## 7. チャンネルの取り下げ

承認したチャンネルに審査基準に反することが分かったら取り下げます（審査基準「取り下げ」）。

1. 「チャンネル」でチャンネル ID を入れて表示する
2. 重さを選ぶ
   - **重い**: 安全を損なう誘い、違法な内容、個人情報の収集、権利侵害 → すぐに取り下げる
   - **軽い**: 事実の小さな誤り、説明と内容のずれ → 先にチャンネル提供者へ修正を求め、期限までに直らなければ取り下げる
3. 取り下げる版を入れる（空欄はすべての版）
4. **散策者に見せる理由**を入れて「取り下げる」

### 通報と権利の申し立てを受けたとき

通報と権利の申し立ては、リストの案内文書の `contact`（窓口のメールアドレス）に届きます。流れと目安は審査基準の[platform チャンネル審査方針](https://github.com/duwenji/yorisoi-platform/blob/main/docs/policies/channel-review.md#取り下げ)と[platform チャンネル審査方針](https://github.com/duwenji/yorisoi-platform/blob/main/docs/policies/channel-review.md#権利の申し立て)にあります。

| 届いたもの | 目安 | すること |
|---|---|---|
| 重い通報（安全を損なう誘い・違法・個人情報の収集） | 24 時間以内 | 確かめて、外すならこの節の手順で取り下げる。確かめるまでの間に外してもよい |
| 軽い通報 | 7 日以内 | 直す必要があれば提供者に求める（期限 14 日。過ぎたら取り下げる） |
| 枠をすり抜けた AI の発言 | 7 日以内 | アプリの固定の指示・出力の確認の直し方を決める（アプリの開発者に回す） |
| 権利の申し立て | 受け付けの返信 3 日・判断 14 日 | 提供者の言い分を 7 日まで待つ。明らかなときは待たずに取り下げる。繰り返し・なりすましは提供者を停止する |

- 取り下げ・停止の理由には、何を受けてか（「通報」「権利の申し立て（受け付けた日）」）を書く。操作の記録に残る
- 通報した人には返信しない。権利の申し立ては、受け付けと判断を申し立てた人に知らせる
- 外したものに問題がなかったときは、提供者に版を上げて申請し直してもらう（取り下げた版は戻せない）

取り下げると、チャンネルはリストから消え、`revoked` に理由とともに 7 日載ります。アプリはパッケージを消して、散策者に理由を知らせます。**元に戻すには新しい版の承認が要ります**（前の版には自動で戻りません）。

## 8. 審査

機械の確認に合格した申請を、審査基準（platform チャンネル審査方針）で確かめて判定します。判定は、機械の確認に合格してから 5 日以内を目安にします（platform CHANNELS C-14）。審査は無料です。

1. 「審査」で、審査待ちの申請（古い順）を開く
2. 「審査を始める」を押す（状態が「審査中」になる。ほかの担当者に任せるときは「審査を戻す」）
3. 申請の情報（説明・タグ・地域・運営への説明）と、機械の確認の結果を確かめる
4. 「パッケージの中身」の「開く」で、`channel.json` とプロンプトの文章、アイコンを確かめる（ブラウザの中で展開する）
5. **AI の一次審査**（platform AI-ROLES H-12）で、AI に気になる箇所を挙げてもらう。キーの扱いは見本と同じ。AI の指摘は判断の材料で、承認・差し戻しは必ず人が決める（パッケージの文章が AI を誘導することがあるので、「気になる点なし」でも 4 と 7 は省かない）。素材集の審査の画面にもある
6. **話させた見本**（審査基準 2.7）を作る
   - サービス（OpenAI か DeepSeek）を選び、**あなたの API キー**を入れる。キーはこのページの中だけに置き、管理システムには送らない（ページを開き直すと消える）
   - 「モデルを読み込む」でモデルを選び、「見本を作る」を押すと、アプリと同じプロンプトで場面ごと（散歩の開始・スポットの解説・再訪・休憩・区切り・終了。チャンネルが話さない場面は除く）に AI が話す
   - 「この見本を審査の記録に残す」で保存する。**2 つのサービスで試す**（審査基準 2.7）
7. 審査基準の項目（2.1 語り口と内容、2.2 安全、2.3 プライバシー、2.5 AI への指示、2.6 素材ときっかけ、2.7 見本）で確かめる
8. 判定する
   - **承認**: パッケージとアイコンが公開され、チャンネルがリストに載る（前に承認した版は置き換え済み）。リストはすぐ作り直される
   - **差し戻し**（直せば承認できる）・**却下**（直しても承認できない）: 審査基準の項目番号つきの理由を 1 つ以上入れる。理由と説明はチャンネル提供者の画面に出る。チャンネルは空き、チャンネル提供者は直して出し直せる
   - 判定には、このページで残した見本が付く。結果はチャンネル提供者にメールで知らせる（下の「チャンネル提供者へのメール」）

- 承認のときに、パッケージが機械の確認のときと同じか（SHA-256）をもう一度確かめる。版の番号が、最後に承認した版以下なら承認できない（`version_not_newer`）
- 審査の記録（だれが、いつ、何を、理由、見本）は申請のページの下に出る

## 9. チャンネル提供者の鍵の移し替え

チャンネル提供者が鍵をなくした・漏れたときの救済です（ARCH-001 D-3・A-15）。

1. チャンネル提供者が画面で新しい鍵を作り、移し替えを申し出る（理由、散策者に見せる文、運営への説明）
2. 運営が「鍵の移し替え」を開く。確認待ちの申し出が古い順に並ぶ
3. **鍵とは別の経路**（登録済みの連絡先への問い合わせなど）で本人確認する。どう確かめるかの手順は、運用を始める前に決める（ARCH-001 未決事項 No.5）
4. 確かめた方法と内容を入れて「承認する」。確かめられなければ、理由を入れて「認めない」（新しい鍵の紐づけは外れる。その鍵のアカウントIDは二度と使えない）

承認すると、次のようになります。

- チャンネル提供者のすべてのチャンネルが新しい鍵に移る。古い鍵で署名した審査待ちの申請は差し戻される
- 公開中の版はそのまま（古い鍵の署名のまま使われ続ける）。**漏れたおそれがあるときは、公開中の版を取り下げるかどうかを検討する**
- 新しい鍵で署名した最初の版を承認すると、リストにその版と移し替え（`publisherChange`）が載り、アプリは散策者に一度知らせる。リストには 90 日載る
- 結果はチャンネル提供者にメールで知らせる

状態を「承認」「認めない」「取り消し」に切り替えると、過去の申し出と本人確認の記録を見られます。

### チャンネル提供者へのメール

承認・差し戻し・却下・取り下げ・移し替えの承認・認めないのたびに、チャンネル提供者の確認済みのメールアドレスへ 1 通送ります（API-001 C-14）。本文は結果、理由（差し戻し・却下の指摘、取り下げの理由、運営のメッセージ）、画面へのリンクだけで、見本や運営の ID は入りません。

- 送れなくても操作は成功します。3 回試して送れなければ、操作の記録に `notification.failed` が残り、警報が出ます
- 送ったものは操作の記録に `notification.sent` として残ります（宛先は残しません）
- **開発用は送りません**。独自ドメイン（ARCH-001 未決事項 No.1）がないため、送る内容を記録するだけです（`notification.sent` の `messageId` が `log-only`）。本番も、ドメインと SES のサンドボックスの解除（ARCH-001 未決事項 No.6）が済むまでは同じです

## 10. 操作の記録

「操作の記録」では、月ごと、または対象ごとに記録を見られます。記録は消しません。

| 対象の書き方 | 例 |
|---|---|
| チャンネル提供者 | `PUB#01J…`（チャンネル提供者の詳細の下のリンクから開ける） |
| チャンネル | `CH#kamakura-history` |
| 鍵セット・署名鍵・公開 | `KEYSET`、`SIGNKEY#k-2026-10`、`PUBLICATION` |

主な操作の名前: `publisher.suspend`・`publisher.resume`・`limits.update`・`channel.revoke`・`signing-key.register`・`keyset.register`・`publication.request`。

## 11. 緊急時の対応

| 事態 | すること |
|---|---|
| 不適切なチャンネルが公開されている | [取り下げ](#7-チャンネルの取り下げ)（重い）。必要ならチャンネル提供者を停止する |
| チャンネル提供者が悪用している | チャンネル提供者を停止し、公開中のチャンネルを取り下げる |
| 署名鍵の漏えい・管理システムの乗っ取りの疑い | 開発・保守の担当者に新しい署名鍵を作ってもらい、新しい鍵を登録して、古い鍵を `revokedKeys` に入れた鍵セットに署名して登録する。ルート鍵は管理システムの外にあるので、これで立て直せる。アプリに届くまで最大 24 時間 |
| ルート鍵をなくした | 鍵セットを作れなくなる。開発用はルート鍵から作り直す。本番は新しいリストになり、アプリの更新が要る。**ルート鍵の写しは必ず複数の場所に置く** |
| リストの期限が近い（概要で警告） | 「公開」で作り直す。失敗するなら開発・保守の担当者へ（警報のメールの宛先を設定していれば、警報も届く。開発用は未設定） |

## 12. 困ったとき

| 画面の表示 | 意味と対処 |
|---|---|
| ほかの人が先に変更しました | 開いている間に、ほかの人（または別のタブ）が同じものを変えた（`precondition_failed`）。読み込み直し、内容を確かめてからやり直す |
| 今の状態ではこの操作はできません | 例: 停止中のチャンネル提供者をもう一度停止した、取り下げ済みのチャンネルを取り下げた（`invalid_state`） |
| この操作をする権限がありません | 運営のグループに入っていない（`forbidden`） |
| 操作が多すぎます | 短い間に操作しすぎた（毎秒 20 回まで）。少し待つ |
| 鍵セットが正しくありません／署名が正しくありません | [5.2](#52-鍵セットを登録する) の拒まれる理由を見る |
| サーバーで問題が起きました | 表示された `instance`（要求 ID）を添えて、開発・保守の担当者へ |
| 手動の公開をしても履歴が増えない | 公開の処理が失敗している。開発・保守の担当者へ（CloudWatch の警報 `PublishFailures` が鳴っている） |
| ログインの画面から進まない | 認証アプリのコードの時刻ずれ、または MFA の端末をなくした。開発・保守の担当者へ |

## 13. スタジオ

スタジオは、素材提供者が出す店や地域のお知らせで、素材の種類の 1 つです（platform [REQ-STUDIO](https://github.com/duwenji/yorisoi-platform/blob/main/docs/requirements/REQ-STUDIO.md)）。運営はスタジオ 1 件ずつは審査しません。**出す素材提供者を承認し、自動の確認の誤りの申し出と、通報されたものに対応します**。判断の基準は platform の[スタジオの決まり](https://github.com/duwenji/yorisoi-platform/blob/main/docs/policies/studio-rules.md)、素材提供者の手順は[スタジオのガイド](studio.md)です。

「スタジオ」タブには、上から次の列が並びます。どれも、対応すると列から消えます。

### 13.1 承認の審査待ち

提供者の申し込み（出す名前・団体・人・載せたいもの・同意したスタジオの決まりの版）を見て、スタジオの決まり 1.3 の 4 項目を確かめます。

| 項目 | 確かめること |
|---|---|
| 1.3.1 | 本人確認ができる。名乗っている団体・人と申し込んだ人が同じ（登録した連絡先・ウェブサイトなどで） |
| 1.3.2 | 出す名前が、ほかの団体・人と紛らわしくない |
| 1.3.3 | 載せたいものが、主に「載せないスタジオ」に当たらない |
| 1.3.4 | 過去にスタジオの承認を取り消されていない |

4 つすべてにチェックを入れると「承認する」が押せます。見送るときは、理由（スタジオの決まりの項目番号を付ける）を入れます。理由は提供者にメールで伝わり、直せるものは申し込み直せます。目安は 5 日です。

承認したあとの提供者は、「提供者」の詳細から **期間を決めて止める**（1〜3 か月。軽い違反を直さない・繰り返すとき。載っているスタジオも届かなくなる）、**止めたのを戻す**、**承認を取り消す**（重い違反・なりすまし・権利侵害の繰り返し。載っているスタジオを消し、申し込み直しは 1 年後から）ができます（スタジオの決まり 4.3）。

### 13.2 申し出

自動の確認に当たって返されたスタジオについて、素材提供者が「確認が誤っている」と申し出たものです。素材提供者の説明、AI が当たったとした項目、音声の書き起こしを見て、「確かめて載せる」か「載せない」（理由を入れる）を選びます。**AI の指摘だけで載せないと決めないでください**。返事の目安は 7 日です。

### 13.3 通報されたスタジオ

3 台以上から、または「安全を損なう」「権利の侵害」で通報されたスタジオは、自動で届けるのを止めています（スタジオの決まり 4.1。警報のメールも届きます）。通報の数と理由、最初の通報の日時、音声の書き起こしを見て決めます。目安は、重いもの 24 時間・軽いもの 7 日です。

| ボタン | 使うとき |
|---|---|
| 問題なし（戻す） | 決まりに反していない。また届くようになる |
| 消す | 決まりに反している。理由（項目番号）は素材提供者にメールで伝わる。繰り返すときは 13.1 の止める・取り消すも考える |

## 14. 一言

一言は、散策者・走る人がその場所に置く投稿で、素材の種類の 1 つです（platform [REQ-NOTES](https://github.com/duwenji/yorisoi-platform/blob/main/docs/requirements/REQ-NOTES.md)）。運営は事前に審査しません。**置く人の同意と置く前の自動の確認で守り、通報されたものに対応します**。判断の基準は platform の[一言の利用規約](https://github.com/duwenji/yorisoi-platform/blob/main/docs/policies/notes-terms.md)です。

「一言」タブには、通報された一言と、締め出した端末が並びます。

### 14.1 通報された一言

3 台以上から通報された一言は、だれにも届けず隠しています（警報のメールも届きます）。置いた端末は運営にも分かりません。

| ボタン | 使うとき |
|---|---|
| 問題なし（戻す） | 利用規約に反していない。また届くようになる |
| 消す | 利用規約に反している。本文も消える。あわせて、置いた端末を締め出せる（締め出さない・7 日・30 日・90 日・期限なし） |

一言の自動の確認（電話番号などの決まった形と、運営の AI）は置くときに済んでいるので、ここに来るのはそれをすり抜けたものです。

### 14.2 締め出し

締め出した端末は、一言を置けません（聞くことはできます）。一覧は、もとの一言（の ID と本文）で示します。「解く」で戻せます。アプリを入れ直すと別の端末として扱われるので、締め出しは完全ではありません。

## 15. 置けない区画

スタジオと一言は、どちらも区画ごとに運営から取る素材なので、置けない区画は両方に効きます（「置けない区画」タブ）。

学校・病院・私有地の周りなど、スタジオも一言も置かせたくない場所を、geohash の 5〜7 文字で足します（5 文字は約 5 km 四方、6 文字は約 1.2 km × 0.6 km、7 文字は約 150 m 四方）。足すと、一言は置けず、スタジオもその区画を選べなくなります。アプリには 5 分以内に効きます。すでに置かれている一言と載っているスタジオは、期限まで残ります。

## 16. その場の素材の配信を止める

不適切なものが一度に広がるなど、1 つずつの対応では間に合わないときは、開発・保守の担当者に頼んで、スタジオと一言の配信をまとめて止めます（[スタジオの手順](../operations/studio.md)「すぐに止める」）。アプリの散歩・走行は続き、スタジオと一言だけが届かなくなります。
